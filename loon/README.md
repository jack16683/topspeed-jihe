# 极速鸡盒 · Loon

知道你的鸡盒到底有多快

## 安装与使用

1. 从仓库首页“一键导入 Loon”安装明文插件。发布人：`jack16683`。两个运行脚本由插件自动下载。
2. 启用脚本及 MITM，沿用已信任的证书。适用 Loon 3.5.1 (983) 及后续兼容版本。
3. 停用匹配同一接口的旧插件或 Body Rewrite。泛匹配的响应观察脚本应排在本插件之后。[Loon 规则说明](https://nsloon.app/docs/Script/script_v2/)
4. 打开历史行程，使 App 实际加载轨迹；之后退出“我的骑行”再进入，刷新单日/月统计。App 已经缓存的旧页面不会因后台计算而自动刷新。
5. 插件参数可选择急刹“严格G / 云端近似”、压弯“日常估算 / 保守估算”。默认严格G与日常估算。更改后重新进入 App 加载相应行程和统计。
6. 可在插件脚本列表运行“极速鸡盒 查看缓存”。这里会显示算法版本、缓存条数以及采样或几何信息不足的行程数。

## 2.1.1 更新

修复车辆首页和车辆列表改写时长整数丢失精度的问题。部分车型的 App 会把首页的 `bindingUserId` 用作车辆信息查询的 `carUserId`。改写后会保留原始数字和类型，沿用 2.1.0 的统计算法及其缓存。

## 算法 2.1.0

### 显示解锁

仅对官方 App 已发出的只读 GET 成功响应处理：HTTP 200，业务码为数字或字符串 `10000`。

在 `vehicleHomePageV2`、`vehicleHomePageV2/<车辆编号>`、`vehicle/list`、`myRideInfo`、`ridetrack_v2` 的 `data` 内递归处理已有字段：

- `vehicleKinds` 为 `1`、`4`、`"1"`、`"4"` 或 `null` 时改为数字 `2`。
- 已有的 `cyclingEventStatisticFlag` 改为 `true`。

保留 `vehicleType`、速度、轨迹、车辆标识及其他字段。加速次数始终来自云端。

### 急刹

**严格G（默认）**：

按纵向减速度而不是降速量计数：候选标准为 **0.3 G，持续至少 0.6 秒**，同一连续过程只计一次，没有经验倍数放大。这是本插件的统计规则，并非厂商官方定义。

要进行完整行程计数，所有有效相邻采样须不超过 **0.25 秒**，并且没有未观测缺口或异常点。否则该行程的本地急刹估算记为“未知”，不回填急刹字段，保留云端原值。

常见的约 10 秒采样无法还原瞬时制动峰值。因此页面原本为 0 且保持为 0，不代表插件确认全程没有急刹；请结合“查看缓存”中的采样不足条数理解。

**云端近似（可选）**：

用低频轨迹中的降速区间拟合旧云端计数口径，在原值缺失或 0 时回填近似次数。它不是物理意义的 0.3 G 急刹检测，也不能证明发生了多少次真实急刹。

仅用于中位采样间隔 5–20 秒的轨迹；采样更密且满足严格检测条件时优先采用严格检测。近似模型排除起始速度低于 10 km/h、降速小于 5 km/h 或区间平均减速度小于 0.02 G 的区间，再使用历史计数拟合系数 0.875。这个系数是统计映射，不是把平均 G 换成瞬时 G。

模型只基于有限的旧计数样本，并按日期分组交叉验证；样本用于研究调参，这属于内部验证，并非独立准确率；缺乏可靠的真实零事件样本，厂商定义也未知。新日期、不同采样方式或其他车辆不保证沿用相同口径。需要严格解释 G 的情况请使用默认模式。

### 压弯模型估算

“压弯”栏只填入模型筛选后的转弯估算，**不是传感器测得的倾角或真实压弯记录**。

- 用路线方向变化识别转弯，累计方向变化至少 30°，考虑定位误差，合并连续弯；区分 S 弯两次转向和掉头，过滤静止漂移。
- 按转弯位置的速度判断，最低 10 km/h 用于排除低速挪车；没有 20 km/h 硬门槛，也不使用整段行程最高速度代替转弯速度。
- 用转弯前后几何点构成的圆弧曲率和该处速度，估算平路稳态模型下的等效倾角；默认“日常估算”达到 **5°** 计入，“保守估算”达到 **10°** 计入。阈值均为本插件自定义的采样尺度筛选指标，不是真实倾角门槛。
- 模型假设人车大致同向倾斜，不知道路面横坡或骑手动作；稀疏 GPS 会把短促小半径弯平滑，可能低估或漏计。估算的 0 也不代表实车一定没有倾斜。

### 轨迹质量

轨迹格式为 `经度,纬度,km/h速度,时间戳[,其他字段]&...`，支持 Unix 秒或毫秒。

按行程的中位采样间隔自适应断段，默认允许其 2.5 倍，限制在 5–60 秒之间。例如约 10 秒采样允许普通的 15–19 秒间隔，长缺口仍会断开。非法坐标、逆序时间和异常位移不会被拼接为事件。

## 缓存与统计

缓存按急刹/压弯配置、账号标记（若请求提供）、车辆、日期、行程 ID 隔离，仅保存标识、日期、次数、算法版本及质量状态，不保存 Token 或轨迹。

- **升级至 2.1.0 后，旧算法缓存会失效。**再次打开行程会重算一次；之后直接复用，包括 0 和“未知”结果，不重复计算。
- 不同配置分别缓存。切回已经使用过的配置会复用该配置缓存；更改参数后加载新的配置即可计算，所有配置共享总容量上限。
- “查看缓存”展示最后运行配置的数据；参数更改后需让 App 发出请求才能看到新配置结果。
- 云端已有非零统计优先保留；后来收到新的非零云端次数时，会更新缓存贡献。
- `myRideInfo` 的日统计和 `analyse/analyse` 的月统计只覆盖已加载的缓存行程。压弯累计仅包含可计算行程，可能只是下界。
- 严格模式下，如果缓存范围内存在急刹未知的行程，不将局部已知次数写成该范围完整的急刹汇总。原始接口在某些时期可能返回 0；保留原值不能解释为脚本确认没有事件。
- 全历史累计字段（如 `bendingTimesTotal`）保持原值；不把部分历史缓存当成全部历史。
- `homeRideInfo` 只在响应已有明确行程 ID，或明确日期且含日统计字段时回填。
- 缓存上限 2000 条、约 90 万字符；保存失败或超限会写日志，当次响应仍可补全，未成功保存的行程下次还会计算。需要重新计算时，可手动运行“极速鸡盒 清空缓存”。

不主动查询服务器，不上传账号或轨迹，不修改请求、车辆设置或固件。

## 源码与验证

运行脚本是明文，算法与响应处理源文件在 `loon/src/`。发布脚本地址固定到版本标签；更新插件即可切换到相应版本。

```sh
node build-loon.mjs
node --test loon/tests/*.test.mjs
node package-loon.mjs
```

自动检查覆盖显示改写、物理阈值、采样断段、几何筛选、缓存复用/失效、未知结果、云端值优先及统计回填。发布前另在本机回放用户提供的历史抓包；真实数据不包含在仓库或源码包中。

离线回放不能替代手机上的运行验证，也不能证明估算次数等于真实事件数。首次安装或更新需要能访问 GitHub 原始文件域名。
