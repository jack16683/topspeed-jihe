# 极速鸡盒 · Loon

本插件保留极速、骑行分析显示开关，新增从 `ridetrack_v2` 轨迹估算**急刹、压弯次数**，并缓存用于已加载行程的日/月统计。算法参考 [RyanYuFish/SpeedHunter-iOS](https://github.com/RyanYuFish/SpeedHunter-iOS/blob/bd17ef6e9ad01ec135aeba8666391e1e259a8234/scripts)，遵循 AGPL-3.0。原仓库版本：`bd17ef6e9ad01ec135aeba8666391e1e259a8234`。

## 安装与使用

1. 将 `outputs/极速鸡盒.lpxe` 发到 iPhone，在 Loon 插件页从文件导入。脚本已打包，不必分别导入 JS。如果系统没有显示 Loon 打开选项，先将文件存入“文件”App，再从 Loon 的插件导入入口选择它。
2. 启用插件、脚本和 MITM，沿用已信任的证书。插件适用 Loon 3.5.1 (983) 及后续兼容版本；尚未在实际手机确认导入与运行。
3. 停用原来匹配相同接口的极速解锁脚本或 Body Rewrite。本插件已经包含 `vehicleKinds=2` 和 `cyclingEventStatisticFlag=true`。保留其他功能插件，但本规则必须排在泛匹配的响应观察脚本之前。
4. 打开App 的骑行记录，点开需要补全的行程，使 App 实际请求轨迹。已有本地页面缓存不一定产生请求，必要时退出重进。
5. 返回并刷新日/月骑行统计。如果统计响应先于轨迹到达，再刷新一次。可在 Loon 手动运行“极速鸡盒 查看缓存”查看已缓存行程数。

Loon 每个响应阶段只选中一条 Response Script；匹配同一 URL 的旧脚本、全域响应观察器或 Body Rewrite 可能让补全脚本无法执行。[Loon 文档](https://nsloon.app/docs/Script/script_v2/)

## 覆盖范围

| 接口 | 行为 |
|---|---|
| `vehicleHomePageV2` / `vehicle/list` | 调整上述两个显示字段，保留 `vehicleType` 等其他字段 |
| `ridetrack_v2` | 已缓存行程直接回填；未缓存时解析 `data[].historyList[].trajectory`，为缺失/0 的急刹、压弯字段计算估算值 |
| `myRideInfo` | 按 `rideRecordList[].date` 补全缺失/0 的 `brakesTimesDay`、`bendingTimesDay` |
| `analyse/analyse` | 按 `rideMonth` 汇总已缓存行程，补全缺失/0 的 `brakesTimes`、`bendingTimes` |
| `homeRideInfo` | 仅在响应含明确匹配的行程 ID，或明确日期且已有日统计字段时补全；实际 App 的这一响应结构仍待手机验证 |

所有云端已有非零统计优先保留。日/月回填是**已加载轨迹的累计估算，可能只是下界**；未打开的历史行程不会自动补齐，不应视为完整官方月报。全历史累计字段如 `bendingTimesTotal` 保留原值，避免把部分缓存当成全部历史。急加速次数等沿用云端数据，没有新增估算。

无车辆标识时仍可补全当前轨迹响应，但不跨响应缓存；不会猜测“最近使用的车辆”。缓存按请求用户 ID（若有）与 VIN 分组，仅保留日期、行程 ID、事件次数，不存 Token 或轨迹。服务端不同接口若提供的用户 ID 不一致，会分入不同缓存组，需实际抓包验证后再适配。

已计算的行程优先读取缓存，跳过轨迹解析、急刹和压弯计算，也不重新写缓存；估算结果为 0 时同样复用。只计算未缓存的行程，兼容此前版本已保存的缓存，不会重复累加。日/月统计仍按缓存求和。

同一行程后续即使收到不同轨迹，也沿用首次缓存结果；需要重新计算时，手动运行“极速鸡盒 清空缓存”，再打开相关行程。该操作只清本插件的估算缓存。缓存最多 2000 条行程、序列化约 90 万字符，超限拒绝保存而不悄悄丢弃旧记录；未成功保存的行程下次打开仍需计算。

## 算法与限制

- 轨迹格式：`经度,纬度,km/h速度,时间戳[,其他字段]&...`。兼容 Unix 秒和毫秒；非法坐标、空速度、逆序时间、超过 25 秒的采样间隙会拆段。少于 4 点的段不参与估算。
- 急刹沿用参考实现的 5/3 点滑窗、15/20 km/h 降速阈值、最小 1.5 秒、0.5 m/s²、按索引合并及 **2.5 倍经验系数**。它是参考作者的经验估计，未在本车标定，不是实测刹车传感器计数。
- 压弯沿用参考实现的航向平滑、20–80 km/h 速度区间、5° 起判、15–90° 累计转角过滤。它只能估计转弯事件，**不能测量车身倾角**。
- 轨迹稀疏、GPS 漂移和云端滤波都会影响结果。没有足够轨迹时保持原数据，不编造事件。
- 仅处理官方 App 已经发出的 GET 请求的成功响应；不主动补抓历史，不需要 Token/appSecret，不修改车辆设置或固件。

## 验证

在项目根目录运行：

```sh
node --test loon/tests/ride-fill.test.mjs
```

16 项离线模拟测试覆盖急刹/转弯/直线、跨请求缓存、非零与零结果命中后跳过计算和写入、新旧行程混合回填、清空后重新计算、车辆/账号隔离、云端值优先、日期与时间戳、异常轨迹、错误响应、存储失败和手动缓存操作。**未执行真实账号 API、真实轨迹或 iPhone/Loon 运行测试。** 打包验证只验证资源绑定及加密往返，不能替代手机导入验证。

明文 `.plugin` 与两个 JS 一并提供，供检查与将来托管；不要把明文 `.plugin` 单文件导入后期待它自动找到未导入的相对路径脚本。当前提供的 `.lpxe` 已包含全部运行资源。
